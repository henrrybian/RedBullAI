## 用户要求

按 `STM32_Buzzer_PWM_Workflow.md` 执行**阶段 0（资料与环境准备）**，且**只完成阶段 0**，不进入阶段 1、不生成任何固件代码。总体目标为 STM32F103ZET6 红牛开发板蜂鸣器 PWM 鸣叫、USART1 作为 Debug 输出、J-Link SWD 单步调试做环境准备。

硬件真相源固定为文档阶段 1 引脚映射表：`BEEP/BOOT1=PB2`、`USART1=PA9/PA10`、`SWD=PA13/PA14`、`CON1` 为 RS232 电平；禁止臆造引脚与 HAL API。硬约束：用户零手写代码；命令兼容 PowerShell；保持 SWD 可调试；每阶段须有验收门与失败回退。

已确认补充范围：本次**包含实际安装动作**（由 AI 生成并执行可静默安装命令后复验）；产出物落盘为**文档 + 一键校验脚本**。

## 产品概述

交付一份「阶段 0 环境就绪报告」和一个「一键校验脚本」。用户只需运行一条命令并把输出回传，即可获得「必须项全部就绪」或「具体缺项清单」的明确判定。报告以分段命令块、对照表、可勾选清单和回退表呈现，作为进入下一阶段的准入门。

## 核心功能

- 环境校验命令清单：逐项检查构建工具、交叉编译器、调试器、器件描述文件、CubeMX 与调试前端，并输出版本号或绝对路径。
- 工具对照表：工具 / 用途 / 预期版本输出 / 缺失时安装方式。
- 依赖就绪判定规则：区分必须项与可选项，并给出基于本机实测的就绪或缺项判定。
- 调试前端探测：能否新建计划、内置终端能否执行命令、上下文引用是否可用、调试扩展是否可安装；不可安装时给出兜底路径结论，且不阻塞阶段 0。
- 硬件操作禁忌清单：带电插拔调试口、电平混接、供电与共地、跳线与启动模式、禁止破坏 SWD 可调试性。
- 实际安装可静默获取的工具链并复验；记录无法静默安装项的官方安装方式。
- 阶段 0 验收门与失败回退表：可观测通过条件，以及安装失败、路径未生效、描述文件缺失、调试器不在 PATH、前端异常、资料打不开等情形的回退动作。
- 一键校验脚本：只读、幂等、一次运行输出可整段回传的结果。

## Tech Stack Selection

- **平台与命令**：Windows + PowerShell（用户硬约束）。不使用 bash 专属语法；含空格或括号的路径一律加引号（尤其 `红牛开发板电路图(RedBull Schematic).pdf` 同时含空格与括号）。
- **交付物类型**：Markdown 报告 + PowerShell 只读校验脚本。**不产生任何 `.c/.h/.s/.ld`、`CMakeLists.txt`、`.ioc`、调试配置或固件代码**。
- **包管理**：本机 `winget v1.29.380`（实测）。因实测到 `msstore` 源协议未接受会直接取消操作，统一使用 `--source winget --scope user --disable-interactivity`，规避协议阻塞、管理员权限与交互挂起。
- **工具链（本机 winget 源实测包 ID，不臆造）**：`Kitware.CMake 4.4.4`、`Ninja-build.Ninja 1.13.2`、`Arm.GnuArmEmbeddedToolchain 14.2.Rel1`；`NordicSemiconductor.JLink 8.18.0`（Nordic 分发版）；`STM32CubeMX` 无匹配包。
- **调试前端**：CodeBuddy IDE（`Plan`/`Craft`/`Ask`、内置终端、`@` 上下文引用、插件市场）；`Cortex-Debug` 可用性待探测，命令行 GDB 为兜底。
- 不引入新框架、模块或第三方依赖；复用文档既有六要素、验证点片段、验收标准与失败回退表。

## Implementation Approach

**策略**：采用「只读基线 → 参数探测 → 条件安装 → 一键复验 → 明确判定」的探测驱动闭环。所有工具路径、版本号、扩展结论均来自本机实测输出，不凭记忆编造；凡未实测到的路径一律以「探测命令 + 待回传」形式呈现。

**关键决策与取舍**：

1. 安装前先跑 `winget install --help` 与 `winget show --id ...` 确认参数写法与包内容，与文档「J-Link 参数先 `--help` 探测」同理，避免编造静默参数。
2. 仅对 winget 可静默获取项执行安装；`J-Link`/`STM32CubeMX` 如实记录为需官方安装包人工完成，不因存在同名包就宣称就绪。
3. 安装后以 `Get-Command`、`Get-ChildItem -Filter` 实测 `bin` 目录与 `arm-none-eabi-gdb`、`JLinkGDBServerCL.exe` 的绝对路径；若不在 PATH，仅追加**当前会话** `$env:PATH`，不改机器级环境变量，保证可回退。
4. `NordicSemiconductor.JLink` 非 SEGGER 官方软件包，**不得假定** `C:\Program Files\SEGGER\JLink\`；以「是否实际存在 `JLinkGDBServerCL.exe`」为判据，缺失则列为缺项并给出官方包安装说明。
5. STM32CubeMX 归为**可选项**（阶段 2 的 `.ioc` 为可选），但 STM32F1 的 `.svd` 为**必须项**；用受限目录递归搜索 `STM32F103*.svd` 探测，未找到则如实列为缺项，并附 CubeMX / Keil Pack 目录搜索方案，路径未实测前不写死。
6. `Cortex-Debug` 不硬装、不预断：按文档最新版只输出探测步骤与「可安装 → 阶段 5 图形化主选 / 不可安装 → 命令行 GDB 兜底」判定规则，两种结论都不阻塞阶段 0 通过。
7. **重要口径修正**：先前 `code --list-extensions`（VS Code CLI，9 个扩展、无 `marus25.cortex-debug`）探测的是 VS Code 扩展，与新版文档要求的「CodeBuddy 插件市场能否搜到 `Cortex-Debug`」不是同一对象，**不作为该结论的依据**；须按文档第 148–151 行以界面/内置终端重新探测并如实记录。
8. 本阶段**不解析原理图 PDF**（文档第 97、107 行明确「仅确认可读，本阶段不解析」），只用 `Get-Item` 确认存在与可读（实测 114821 字节），不调用 PDF 解析能力，不越界进入阶段 1。

**性能与可靠性**：一键脚本为约 10 项线性探测，时间复杂度 O(n)、单次运行秒级；唯一潜在热路径是 SVD 递归搜索，限定在 CMSIS Pack / CubeMX / Keil 常见根目录并配合 `-ErrorAction SilentlyContinue` 与结果条数上限，避免全盘扫描。安装阶段瓶颈为 winget 网络 I/O，采用逐项安装、失败即记录并回退、不盲目重试。脚本只读、幂等、无网络、不写系统状态，可在任意阶段门重复运行。

**避免技术债**：直接复用文档第 133–144 行「验证点」PowerShell 片段作为脚本内核，第 153–159 行「验收标准」与第 161–171 行「失败回退」原文作为报告章节，附录 B 勾选 #1/#2/#3/#33 与附录 F 硬件速查卡作为事实来源；不新建自定义框架或配置格式。

## Implementation Notes

- **复用与只读**：`STM32_Buzzer_PWM_Workflow.md` 与原理图 PDF 仅作事实来源，**不修改**。仅新增 `docs/env_check.md`、`scripts/env_check.ps1`。
- **PowerShell 细节**：使用 `Get-Command -ErrorAction SilentlyContinue`、`Select-Object`、`Select-String`、`Test-Path`；禁止命令链连接符、空设备重定向等 bash 专属写法；含空格或括号路径全部加引号。
- **输出与日志**：脚本输出结构化、单行、可直接整段复制回传；每行带明确 `PASS`/`FAIL` 或 `FOUND`/`MISSING` 与版本号或绝对路径；不打印大目录内容、不含敏感信息；安装错误只记录退出码与首行错误文本。
- **影响面控制**：安装动作逐项取得批准；优先 `--scope user`；PATH 仅当前会话追加；不接板、不上电、不烧录、不改跳线、不写 option bytes、不启用读保护。
- **保持 SWD 可调试**：硬件禁忌清单覆盖 `JP6 JTAG_SEL` 设为 SWD 可用模式、`JP8 BOOT0=0`（主 Flash 启动，单步必需）、`J5` pin1 `Vref` 接 3V3 且偶数脚 GND 共地、禁止调试口 remap/关闭；并明确 `CON1`/`CON2` 经 `ST3232` 为 RS232 电平不可直连 USB-TTL，TTL 须从扩展排针取 `PA9/PA10` 并共地；5V 仅供蜂鸣器，禁止接到 3.3V 引脚；禁止带电插拔 JTAG/SWD。
- **版本风险提示**：实测 `Kitware.CMake` 为 4.4.4，其对 `cmake_minimum_required` 最低版本要求较严，阶段 2 生成 `CMakeLists.txt` 时需留意；本阶段**只记录版本、不生成**该文件。
- **验收门与失败回退**：报告须含可观测通过条件（四条 `--version`、CodeBuddy 环境可用、调试扩展结论、`JLinkGDBServerCL.exe` 与 `.svd` 绝对路径、AI 明确判定）与回退表（winget 失败/权限不足、PATH 未生效、SVD 找不到、调试器不在 PATH、扩展搜不到且需配置扩展市场地址、内置终端或 Plan 模式异常、PDF 打不开）。

## Architecture Design

沿用文档既有的线性「阶段门」结构，不引入新架构模式：

- **资料层（只读）**：`STM32_Buzzer_PWM_Workflow.md`（六要素、验证点、验收标准、失败回退、附录 B/F）、原理图 PDF（仅确认可读）。
- **探测与安装层**：CodeBuddy 内置终端执行 PowerShell；winget 负责可静默安装项；所有结果以实测输出为准。
- **交付层**：`scripts/env_check.ps1`（一键只读校验）与 `docs/env_check.md`（清单、对照表、判定规则、禁忌、验收门、回退、本机实测记录）。
- **判定层**：用户运行一键命令并回传输出，AI 对照验收门给出「必须项全部就绪」或具体缺项清单，并指向失败回退动作。

数据流：文档六要素 → 生成脚本与报告 → 本机执行产出结构化输出 → 回传 → AI 就绪判定 → 通过（归档、可进阶段 1）或按回退表修复后重验。组件关系简单，不附加架构图。
