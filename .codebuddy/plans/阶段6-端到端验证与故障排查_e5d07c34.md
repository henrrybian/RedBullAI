## 用户要求与阶段门

- 只执行阶段 6（工作流 654–720 行 + 附录 B 全表 + #30–32），不修改任何源码/配置；本阶段唯一动作是文档生成 + 端到端复验 + 报告回填。
- 硬约束（继承工作流 666–671 行 + 用户补充）：
  1. 验收动作必须可观测（命令输出、终端日志、断点命中、变量值、GPIO 电平、听感描述），禁止不可验证表述；无示波器用「日志 + 变量观察 + `GPIOB->ODR` 电平佐证」替代波形项。
  2. 端到端按固定顺序列出，任何一步失败标注回退阶段（工作流 689–700 行验证点表 + 712–720 行回退矩阵）。
  3. 烧录/下载动作（F5 与 flash.ps1）每次执行前需用户**当轮显式授权**；J-Link FW 升级弹窗一律取消。
  4. 勾选表与排查表覆盖 9 项必覆盖现象（含 GDB Server 首次 Timeout）。
  5. 明确仪器项与替代项，保证无示波器完成主要验收。
  6. 「验收通过」判定 = 工作流 704–710 行五条**同时满足**。
- 所有验收动作在 CodeBuddy 内完成：命令/GDB 序列在内置终端执行，图形化调试在调试视图进行，证据以文本/截图回传判定；用户零手写代码。

## 关键决策（均有依据）

1. **无示波器路径为主**：#23 波形项以 `buzzer_sequence.md` 第 4 节四重替代（变量四件 / 段日志 / `ODR` bit2 电平 / 听感时序 ±50 ms）闭环；原始波形列为可选仪器加分项。
2. **勾选表口径三分**：🔁 = 已有归档证据 + 本次复验待回填（#1–29、#33、#34）；☐ = 本次端到端新产生（#30–32）；不复述归档结论，只复验。
3. **Timeout 处置固化**：GDB Server 首次 `Timeout` 按 `stage5_report.md` 3.1 定性（瞬时性，非配置缺陷）→ T0 进程/端口检查 + 重试一次；连续 2 次失败才切兜底 `scripts/debug_gdb_cmds.txt`。
4. **阶段 5 计划补录**：原阶段 5 会话未落盘计划文件，按 `stage5_report.md` 事实补录归档（不新增报告未记录内容），满足 #33「每阶段一份计划」。
5. **证据回填唯一出口**：所有复验证据统一进 `docs/delivery_report.md`，不散落多处，保证报告即最终归档物。
