# 全 AI 零代码创建本工程：复盘与后续开发指引

> **一句话主线**：我没有写一行代码，只做了三件事——给资料、给指令、做物理动作；AI 用「阶段门」把每一步都变成「先实测探测 → 再生成 → 编译/烧录实测 → 留证据 → 审阅过关」，7 个阶段滚下来，工程就从两张 PDF 变成了会响、会打印日志、可单步的固件。

本文是作者本人复盘，目的有两个：说清这个工程是怎么被"聊"出来的；给后续开发一套可复制的套路。

---

## 0. 30 秒总纲

| 角色 | 分工 |
| --- | --- |
| **我（人）** | 给资料、下指令、做 AI 做不了的物理动作（接跳线、上电、听蜂鸣器、回传日志、当轮授权烧录） |
| **CodeBuddy（AI）** | 解析资料、生成全部源码与配置、跑构建、驱动调试器、写证据文档、给判定 |

关键机制：**引脚映射表是唯一硬件真相源**；**一次只做一个阶段，一个阶段一个 Plan**；**每一步都要有可观测证据，禁止"配置正确"这种没法验证的话**；**不知道的就先探测，绝不凭记忆编造**。

工程最终状态：蜂鸣器按"三短—停 0.6s—一长 0.8s—静音 2s"循环鸣叫；USART1 115200-8N1 打印启动与段切换日志；J-Link SWD 下 F5 一键编译→下载→停在 `main`，断点可看四个状态变量变化。**阶段 6 的最终端到端清单（10 步）与交付报告回填尚待执行，判定时如实标注，未虚报通过。**

## 1. 我给了 AI 什么资料

资料分两类：一类是开局给的"原料"，一类是过程中 AI 自己生成、再被下一阶段引用的"中间产物"。后者是这个套路能滚起来的关键。

### 1.1 开局原料

| 资料 | 作用 | 可核实出处 |
| --- | --- | --- |
| `红牛开发板电路图(RedBull Schematic).pdf`（3 页矢量，114,821 B） | 阶段 1 解析出 MCU、蜂鸣器网络、串口、SWD、跳线，锁定引脚映射表 | `docs/hardware_pins.md` |
| `红牛开发板用户手册(RedBull Manual).pdf` | 阶段 2 补充 JP5/JP6/JP8/JP9、BOOT0、板卡版本等风险项 | `docs/stage2_manual_notes.md` |
| 官方 `STM32CubeF1 V1.8.7` HAL + CMSIS 包（111 文件 / 6,068,581 B） | 阶段 2 提供 HAL 源、启动文件、链接脚本，逐文件 SHA256 留证 | `docs/stage2_hal_source.md` |
| `STM32F103xx.svd`（Keil Pack，867,312 B） | 阶段 1 提供寄存器地址/位定义；阶段 5 供外设视图 | `docs/env_check.md` 8.3 节 |
| 工作流方案 `STM32_Buzzer_PWM_Workflow.md`（先让 AI 写出来，再照着执行） | 全工程的"剧本"：每阶段输入、提示词、产出、验证点、验收、回退 | 工程根目录 |

### 1.2 过程中沉淀、被后续阶段 `@` 引用的中间产物

`docs/hardware_pins.md`（锁定版唯一真相源）→ `docs/env_check.md`（工具绝对路径）→ 各 `stageN_report.md` → `docs/build_commands.md` / `debug_guide.md` → `.codebuddy/plans/` 里每阶段一份归档计划。

**这一条最值得学**：每个阶段结束时把结论写成文档并归档，下个阶段用 `@` 引用它，而不是重新问一遍。这样 AI 不重复猜测、不前后矛盾，换阶段就像接力。

## 2. 我给了 AI 什么指令

### 2.1 指令的固定结构（复制这个模板）

每条生成指令都是五段式：

1. **角色**：让 AI 以嵌入式固件工程师身份执行；
2. **输入上下文**：`@` 引用本阶段的资料与上阶段归档；
3. **硬约束**：零手写代码、命令兼容 PowerShell、SWD 口不能复用、不臆造 API/路径/引脚；
4. **期望产出文件清单**：逐个列出要新建/修改的文件与每个文件的职责；
5. **验收命令**：写明跑什么命令、看什么输出才算过。

在每个阶段内部，再套"六要素"：**输入 / AI 提示词 / 产出物 / 验证点 / 验收标准 / 失败回退**。

### 2.2 我下的指令，本质是三类

| 类别 | 典型原话（摘自各阶段计划"用户要求"） | 作用 |
| --- | --- | --- |
| **范围锁死** | "只执行阶段 3，阶段 4 业务与阶段 5 调试配置一律不越界" | 防止 AI 一次干太多、互相污染 |
| **零臆造 + 先探测** | "由 AI 先实测探测再获取官方依赖"、"J-Link 参数先用 `--help` 实测，不凭记忆写"、"launch.json 每个字段在扩展 package.json 核实后才写入" | 所有路径、版本、参数来自实测输出 |
| **授权与可观测** | "必须先由用户显式授权烧录 + 人工确认 BOOT0=0 闭环"、"验收标准必须是可观测动作" | 物理动作由人把关，结论靠证据 |

全部指令都在 Plan 模式下下达：一个阶段一个 Plan，`READY` 审阅就是验收门，`BUILDING` 暂停/微调就是失败回退，`FINISHED` 归档给下一阶段；局部修补切 `Craft`，概念核对切 `Ask`。

## 3. 目标是什么

- **功能目标**：STM32F103ZET6（LQFP144 / Cortex-M3 / HSE 8 MHz → SYSCLK 72 MHz）红牛板，蜂鸣器以 PWM 方式鸣叫，USART1 作 Debug 输出，J-Link SWD 可单步。
- **过程目标（更重要）**：用户全程零手写代码——所有 `.c/.h/.s/.ld/CMakeLists.txt`、调试配置均由 AI 生成，人只做物理动作。
- **验收目标**：附录 B 共 **34 项**逐条对照证据；验收语句必须是命令输出、终端日志、断点命中、变量值、GPIO 电平、听感描述这类可观测事实。

## 4. 遇到的问题与解决办法（追问弹药库）

每一条都是"实测发现 → 定性 → 处置 → 留证"的闭环，不是猜出来的。

| # | 现象 | 根因 / 定性 | 解决办法 |
| --- | --- | --- | --- |
| 1 | 原理图信息是 PDF，字段可能无法确认 | 图纸事实与电路推断混在一起会误导生成 | 用 pdf 能力抽文字层 + 渲染存疑页；逐字段标"事实/推断 + 证据页码 P1/P2/P3 + 置信度"；确认不了的写"待人工确认"并给实测方法 |
| 2 | 要知道 PB2 是有源/无源、高/低有效，但"不许编译工程" | 常规办法要写个 GPIO 测试程序，违反零编译约束 | 用 J-Link/GDB 经 SWD 在内核 halt 态**直写内存映射寄存器**：`RCC_APB2ENR` 开 GPIOB 时钟 → `GPIOB_CRL` 配推挽 → `BSRR/BRR` 置位/清零 → `x/1xw` 读回；地址全部从实测 SVD 取，不 `file`、不 `load` 任何 elf |
| 3 | 阶段 2 开工前没有 HAL 源（唯一硬阻塞） | 用户要求不装 CubeMX、全命令行 | 先实测探测本机包/缓存/Keil Pack/网络，再取官方 V1.8.7 包；只复制 RCC/GPIO/UART/TIM/CORTEX 等最小必需集，来源、版本、逐文件 SHA256 全部写进 `stage2_hal_source.md` |
| 4 | CMake 是 4.5.0-rc3 预发布版 | 新版对 `cmake_minimum_required` 策略要求更严 | 在 `CMakeLists.txt` 用兼容声明，每次验收以实际 `cmake --version` 复核 |
| 5 | 首次构建报缺 `Legacy/stm32_hal_legacy.h` | 最小源集合漏了官方头文件 | 按官方包补齐该头，并把补件动作同步写进证据文档 |
| 6 | `printf` 往哪重定向 | 直觉写 `__io_putchar`，但实测链接规格是 `nano.specs + nosys.specs` | 实测 `libg_nano.a` 引用 `U _write`、`libnosys.a:write.o` 提供 `T _write`、而 `__io_putchar` 命中数为 0 → 改强定义 `_write`；原型用 `_READ_WRITE_RETURN_TYPE` 避免 conflicting types；工具链文件不动 |
| 7 | 串口日志不是一行一行出，单步顺序对不上 | 裸机 `_isatty` 返回 0 导致 stdout 全缓冲 | 初始化里 `setvbuf(stdout/stderr, NULL, _IONBF, 0)` 强制无缓冲；断点单步实测"停住时无日志、`next` 后整行出现" |
| 8 | J-Link halt 到 `pc=0x1FFFF3B2/3B6`（System Memory） | `BOOT0` 非 0，从系统存储器启动，不是主 Flash | 由我人工把 `BOOT0` 改到 `2-3` 再上电；只读 halt 复测 `PC=0x08004FE6` 闭环；**算法不改锁定版硬件表，只如实登记差异** |
| 9 | 手册表 2 的 `BOOT1(JP8)/BOOT0(JP9)` 编号与锁定版相反 | 板卡版本/文档口径差异 | 以实测与用户回报为准，手册差异单列在报告，不覆盖已锁定的 `hardware_pins.md` |
| 10 | 每次复位日志前多一个字节 `0xFC`（阶段 4 是 `0xF8`） | 复位瞬间 RS232 线路毛刺，非固件输出、非波特率/编码问题 | 如实登记，并把"无乱码"的口径限定为**日志正文**，不含前导杂散字节 |
| 11 | F5 首次报 `Failed to launch jlink GDB Server: Timeout` | 瞬时性（USB 枚举/安全软件扫描），不是配置缺陷 | 按 T0 查进程与端口、手工启动 GDB Server 二进制验证存活、重试一次即成功；固化规则"再遇同现象 T0+重试一次，连续 2 次失败才切兜底" |
| 12 | 不确定 Cortex-Debug 能否安装 | 前端可用性未实测 | 方案一开始就写"图形化主选 + 命令行 GDB 兜底"双路径，各自带前提、验收、回退；阶段 0 实测扩展可用后走主选，兜底保留未启用 |
| 13 | 没有示波器，怎么验波形 | 仪器项缺测 | 用四重替代闭环：四个 `volatile` 变量 + 段切换日志 + `GPIOB->ODR` bit2 电平 + 用户听感时序（±50 ms）；原始波形列为可选加分项 |
| 14 | winget 安装常被协议/管理员权限卡住 | `msstore` 源协议未接受会直接取消 | 统一 `--source winget --scope user --disable-interactivity`；PATH 只追加当前会话、可回退 |

**踩坑的共同规律**：凡是想"凭记忆直接写"的地方（寄存器地址、J-Link 参数、重定向方式、配置文件字段、跳线编号）几乎都会出问题；凡是"先探测再写、写完留证据"的地方都一次过。

## 5. 这套方法为什么成立（机制）

1. **唯一真相源（DRY）**：硬件信息只在 `docs/hardware_pins.md` 锁定一次，后续所有提示词引用它，不硬编码 `TIMx_CHy`/`USARTx`。换板或改引脚只改一处。
2. **阶段门 + 一阶段一 Plan**：7 个阶段（0 环境 → 1 原理图 → 2 骨架 → 3 串口 → 4 PWM → 5 调试 → 6 验证），每个阶段有验收门，过了才进下一个；审阅即门禁，失败即回退，归档即交接。
3. **零臆造**：工具路径、版本号、寄存器位、配置字段、HAL API 一律来自实测输出（SVD、`--version`、`--help`、`package.json`、map/nm 文件）。
4. **可观测验收**：拒绝"配置正确"，只认命令退出码、日志字节、断点命中、变量变化、ODR 电平、听感描述。
5. **授权边界**：烧录/下载每次都要用户**当轮显式授权**（本次授权不沿用）；AI 不改跳线、不飞线、不写 option bytes、不启读保护、不升 J-Link FW。
6. **影响面控制（Blast radius）**：每阶段明确"只读哪些文件、只新建哪些文件"，已归档的文档和 PDF 一律不改；临时脚本用完即删，GDB Server 会话 `PORT_2331_FREE`、无残留进程。

## 6. 后续开发指引

### 6.1 在这个工程里加新功能（沿用套路）

1. **新开一个阶段**：在 `.codebuddy/plans/` 建新 Plan，先写清"只做什么、不碰什么"，`@` 引用锁定版 `hardware_pins.md` 与最近一份 `stageN_report.md`。
2. **下五段式指令**：角色 + 输入上下文 + 硬约束（零手写代码/PowerShell/SWD 可用/不臆造）+ 产出文件清单 + 验收命令。
3. **先探测再生成**：涉及新外设时，先查 SVD 确认寄存器、先 `--help` 确认工具参数、先确认 HAL 模块是否已在 `stm32f1xx_hal_conf.h` 打开。
4. **保持职责二分**：耗时运算/除法放主循环，中断里只做计数与置位（现有 PWM 就是"中断=波形发生器、主循环=Buzzer_Tick 序列推进器"）；不在 ISR 里 `printf`，不 `HAL_Delay`，不动态分配。
5. **烧录前停下来**：确认 `BOOT0=0`（只读 halt 看 `PC` 是否落在 `0x0800xxxx`），等用户当轮回复"可以烧录"。
6. **写完立即留证**：新报告写进 `docs/`，归档 Plan，更新 `docs/acceptance_checklist.md` 的勾选表；没实测的项标"待人工确认"，不虚报。

### 6.2 换一个工程复制这套方法

- 先让 AI 产出**工作流方案文档**（阶段 0–6 六要素），再按方案逐阶段执行——"先写剧本，再演戏"。
- 开局把**原理图 PDF + 用户手册 + 官方 HAL/CMSIS + SVD**一次性给齐；没有的如实说没有，让 AI 走探测/回退路径。
- 第一个硬件阶段必须先产出**锁定版引脚映射表**，后面所有阶段都引用它。
- 全程坚持"一个阶段一个 Plan、READY 审阅、可观测验收、当轮授权"，不要图快让 AI 一口气做完。

### 6.3 红线（任何时候不要破）

- 用户零手写代码；所有源码/配置由 AI 生成。
- 不复用 PA13/PA14，不做 SWJ remap，不关 DBGMCU，Debug 固定 `-O0 -g3`，禁用 SWO/RTT。
- 有源蜂鸣器不做变频改变音调的逻辑（频率字段只代表通断节奏）。
- 不凭记忆编造引脚、HAL API、工具路径、调试器参数。
- 验收结论只写可观测事实，没测的写"待人工确认"。
